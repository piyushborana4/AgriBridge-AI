# AgriBridge AI — Data Provenance & Integrity Architecture (Phase 4.5)

## 1. Executive Summary & Principles
AgriBridge AI is engineered around the principle of **Honest, Traceable, and Verifiable Agronomic Data**. 

Unlike conventional prototypes that invent or simulate indices (such as generating synthetic NDVI from crop health scores or presenting spatial interpolations as physical soil tests), AgriBridge AI enforces strict data provenance, explicit uncertainty labeling, and deterministic validation across all data streams:
1. **Never fabricate ground truth:** If an authentic Earth observation or laboratory test is absent, the platform explicitly classifies the stream as `MODELED`, `FALLBACK`, or `UNAVAILABLE`.
2. **Deterministic Evidence Citation:** AI recommendations generated by Google Gemini are constrained by structural JSON schemas and cannot cite hallucinated signals or fabricate telemetry IDs.
3. **Provider Priority Hierarchy:** Verified farmer laboratory tests take precedence over geospatial pedological estimates, which in turn are strictly tagged with spatial resolution (250m) and uncertainty ranges.

## 2. Canonical Data Provenance Model

Every environmental, meteorological, and pedological telemetry object is wrapped inside a standardized `DataEnvelope<T>` containing explicit `DataProvenance` metadata:

```typescript
interface DataEnvelope<T> {
  data: T | null;
  provenance: DataProvenance;
  quality: QualityScore;
  warnings: string[];
}

interface DataProvenance {
  sourceType: 'satellite' | 'weather' | 'soil' | 'lab_test' | 'sensor' | 'derived' | 'farmer_input' | 'ai';
  provider: string;              // e.g. "Copernicus Data Space Ecosystem (CDSE)", "Open-Meteo"
  dataset?: string;              // e.g. "Sentinel-2 Level-2A (Bottom-of-Atmosphere)"
  observedAt?: string;           // ISO 8601 acquisition timestamp
  retrievedAt: string;           // Sync timestamp
  spatialResolution?: number;    // In meters (e.g. 10m for Sentinel-2, 250m for SoilGrids)
  temporalResolution?: string;   // e.g. "5-Day Revisit", "Hourly Telemetry"
  quality: 'high' | 'medium' | 'low' | 'unknown';
  confidence: number;            // 0 - 100%
  status: 'REAL' | 'MODELED' | 'USER_PROVIDED' | 'DERIVED' | 'FALLBACK' | 'UNAVAILABLE';
  isSynthetic: boolean;
  isFallback: boolean;
  freshnessStatus: 'fresh' | 'aging' | 'stale' | 'unknown';
  notes?: string;
  methodology?: string;
}
```

## 3. Provider Hierarchies & Data Invariants

### 3.1 Satellite & Earth Observation Stream
* **Primary Provider:** Copernicus Data Space Ecosystem (CDSE) STAC API (`https://stac.dataspace.copernicus.eu/v1/search`) querying Sentinel-2 MSI Level-2A surface reflectance products (`collection: "sentinel-2-l2a"`).
* **Observation Formula:**
  $$\text{NDVI} = \frac{\text{B08 (NIR)} - \text{B04 (Red)}}{\text{B08 (NIR)} + \text{B04 (Red)}}$$
* **Cloud Masking:** Passes with cloud cover $>30\%$ are rejected or penalized with confidence degradation.
* **Degraded/Offline State:** When no cloud-free pass exists or backend STAC proxy is unreachable, status is set to `DataStatus.UNAVAILABLE` with `data: null`. **No synthetic NDVI is generated.**

### 3.2 Pedological (Soil) Stream
* **Priority 1 (Ground Truth):** Farmer Laboratory Soil Test (`SourceType.LAB_TEST`, `DataStatus.USER_PROVIDED`). High confidence ($95\%$) with verified lab name, testing date, and sampling horizon ($0-15\text{ cm}$).
* **Priority 2 (Connected IoT):** Connected in-situ soil probes (`SourceType.SENSOR`, `DataStatus.REAL`).
* **Priority 3 (Modeled Estimate):** ISRIC SoilGrids 2.0 (`SourceType.SOIL`, `DataStatus.MODELED`). Explicitly tagged with $250\text{m}$ spatial resolution, baseline model name, and uncertainty range ($\pm 15-20\%$).
* **Priority 4 (Unavailable):** When farm profile lacks coordinates and lab tests, marked `DataStatus.UNAVAILABLE`.

### 3.3 Meteorological (Weather) Stream
* **Primary Provider:** Open-Meteo High-Resolution NWP API (`https://api.open-meteo.com/v1/forecast`).
* **Live Telemetry:** Marked `DataStatus.REAL`, `isLive: true`, `sourceBadge: 'LIVE'`.
* **Climatological Baseline (Fallback):** In case of network interruption or API unavailability, regional calibrated normals are supplied, explicitly marked `DataStatus.FALLBACK`, `isLive: false`, `sourceBadge: 'MODELED ESTIMATE'`.

## 4. Freshness Horizons & Staleness Decay

Data age is actively computed and penalized by the `DataFreshnessEngine`:

| Stream | Fresh Horizon | Aging Horizon | Stale Horizon | Penalty Action |
| :--- | :--- | :--- | :--- | :--- |
| **Meteorology** | $< 3\text{ hours}$ | $3 - 12\text{ hours}$ | $> 12\text{ hours}$ | Confidence dropped from 30 pts to 15 pts; alert badge shown |
| **Earth Observation** | $< 5\text{ days}$ | $5 - 12\text{ days}$ | $> 12\text{ days}$ | Confidence dropped from 30 pts to 15 pts; flags pending overpass |
| **Soil Lab Test** | $< 180\text{ days}$ | $180 - 365\text{ days}$ | $> 365\text{ days}$ | Stale lab test warning; recommendation to re-sample soil |

## 5. Structured Gemini Schemas & Output Sanitization

All AI endpoints communicate with Google Gemini (`gemini-2.5-flash`) using strict `responseSchema` parameters and server-side post-validation:

1. **Crop Doctor (`cropDoctorSchema`):**
   * Enforces strict enums for `plant_part`, `diagnosis_category` (`disease`, `pest`, `nutrient_deficiency`, `abiotic_stress`, `healthy`, `uncertain`), and `severity`.
   * When confidence $<70\%$, automatically sets `needs_expert_review: true`.
2. **AI Advisory (`advisorySchema`):**
   * Requires non-empty action plans, strict priority ratings (`low`, `medium`, `high`), and clear operational urgency (`today`, `this_week`, `monitor`).
3. **Farm Intelligence Evaluator (`farmIntelligenceSchema`):**
   * AI-generated recommendations must link to deterministic evidence IDs (e.g. `SIG-WX-TEMP-001`, `SIG-SAT-NDVI-001`).
   * **Anti-Hallucination Sanitizer:** If the model cites non-existent evidence IDs, the validator intercepts the response, strips hallucinated IDs, and logs a validation violation.

## 6. Verification & Automated Test Suites

The test suite consists of 28 automated tests across four test runners:

```bash
# Run all deterministic intelligence, provenance, and schema tests
node src/services/intelligence/__tests__/runAllTests.js
```

1. `goldenTestRunner.js`: 10 agronomic golden test cases + AI safety validator + scenario simulator (12/12 passing).
2. `provenanceTests.js`: DataEnvelope initialization, soil priority hierarchy, freshness engine (3/3 passing).
3. `antiFabricationTests.js`: Satellite anti-fabrication, uncertainty labeling, weather telemetry separation (6/6 passing).
4. `geminiSchemaTests.js`: Schema validation, enum enforcement, hallucinated ID stripping (7/7 passing).
